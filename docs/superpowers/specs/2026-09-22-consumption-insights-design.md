# LinYu 消费刷新与趋势设计

## 目标

本轮交付解决两个用户可见问题：桌面小组件的“上次消费”在结算后仍显示旧值，以及账单页缺少消费统计与趋势。同时完成代码审查文档中四项低耦合优化，不引入新的大型依赖，不改变开关阀安全语义。

## 范围

本轮包含：

1. 结算成功后统一触发桌面小组件刷新。
2. 结算金额暂时未知时持久化待核对信息，并在后续账单加载时按订单号补写对应设备的上次消费。
3. 账单页新增“近 7 天 / 本月”消费统计和轻量趋势图。
4. 将结算日期解析迁移到线程安全的 `java.time`。
5. 登录请求结束后清空密码或短信验证码。
6. 将相机声明为非必需硬件，并显式标记 CameraX 实验 API。
7. 同步 CHANGELOG 和项目文档。

不包含第三方图表库、长期后台轮询、Room/DataStore 迁移、完整 Lint 清零、CI、全局 UI 重构或账单分页。

## 上次消费数据流

### 正常结算

`ShowerController.settleAmount` 拿到非零金额后，继续通过 `PrefsHelper.recordConsume(snCode, amount)` 按设备保存金额。App、自动关停服务以及通知栏/小组件停止路径都必须在结算调用结束后刷新桌面小组件，使新金额立即进入 RemoteViews。

零消费不覆盖历史“上次消费”，延续当前产品语义。金额为 `null` 表示尚未确认，不能显示为零。

### 延迟到账

结算两条查询路径均未拿到金额时，持久化一条待核对记录：`snCode`、`orderNo`、`startedAt`。后续 `loadBills` 拉到完整账单后按以下顺序匹配：

1. `orderNo` 非空时精确匹配 `BillDTO.orderNo`。
2. 仅为兼容缺少订单号的旧记录，使用设备名与开始时间窗口匹配。

匹配到正金额后写入对应设备、删除待核对记录并刷新小组件。匹配到明确零金额时只删除待核对记录。未匹配则保留，等待下次页面进入或下拉刷新；记录设置有限保留期，避免永久积累。

### 并发与幂等

重复结算和重复账单刷新允许多次写入同一金额，最终结果一致。待核对记录按 `snCode` 区分，不能让一台设备的账单覆盖另一台设备。

## 消费统计

`MainViewModel` 同时保存两份视图：

- `billList`：最近 20 条，继续服务现有列表和余额估算，不改变行为。
- `billHistory`：本次从最近三个月接口取得的完整结果，用于统计与待结算核对。

新建纯 Kotlin 统计模块，将可解析的账单转换为每日数据点。无效日期或无效金额不进入统计，但原始账单仍显示在列表。统计使用设备本地时区，金额按元计算。

### 近 7 天

包含今天在内的连续 7 个自然日。没有账单的日期补零。统计总消费、消费次数和单次平均金额。

### 本月

包含本月 1 日至今天。没有账单的日期补零。统计字段与近 7 天一致。

## 趋势界面

余额卡与账单列表之间增加一个独立的“消费趋势”区块：

- 顶部使用“近 7 天 / 本月”分段控件。
- 展示总消费、消费次数、单次平均金额三个紧凑指标。
- 使用 Compose `Canvas` 绘制折线、数据点和轻量面积填充，不引入图表依赖。
- 横轴只显示少量均匀日期标签，纵向通过最高点自适应；全零数据使用稳定的最小量程。
- 点击或拖动数据点时展示日期、当日金额和次数。
- 空数据仍显示零值趋势，不用错误态替代正常的“暂无消费”。

组件遵循现有主题颜色、边框和圆角，不嵌套卡片，不改变账单详情与代扣操作。

## 优化文档事项

### 线程安全日期解析

用不可变、线程安全的 `DateTimeFormatter` 替换 `ShowerController` 共享的 `SimpleDateFormat`。兼容现有三种服务端格式，并为每种格式和非法输入增加单元测试。

### 登录敏感字段

密码登录请求完成后在 `finally` 清空密码，验证码登录请求完成后清空短信验证码；成功和失败路径一致。手机号保留，方便失败后重试。

### 相机兼容与实验 API

Manifest 增加 `android.hardware.camera` 且 `required=false`。在使用 `ImageProxy.image` 的分析器处添加官方 CameraX `ExperimentalGetImage` opt-in，不改变扫码流程。

## 测试与验收

纯逻辑单元测试覆盖：

- 三种日期格式与非法日期。
- 7 天和本月补零、跨月边界、同日多笔、无效金额。
- 待核对账单按订单号匹配、多设备隔离、过期清理。
- 空消息等既有回归测试继续通过。

构建验证包括 `testDebugUnitTest`、`assembleDebug`、`lintDebug` 和签名 Release 构建。Lint 历史遗留问题如未全部清零，需要明确报告剩余项，不建立静默基线。

验收结果：结算成功后小组件立即更新；金额延迟到账时，在下次账单同步后自动补写；趋势统计与完整三个月数据一致；APK 可安装且签名有效；不推送 GitHub。
