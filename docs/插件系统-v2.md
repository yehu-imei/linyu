# 插件系统 v2

Android 和 iOS 都支持 v2。插件由清单描述，功能由客户端内置并按插件 ID 与能力标识匹配。权限字段用于兼容性校验和详情展示。

---

## 1. 兼容性检查

| 字段 | 用途 |
|---|---|
| `apiVersion` | 指定插件依赖的客户端能力版本，当前上限为 2 |
| `minAppVersion` | 指定最低 App 版本，按数字逐段比较 |
| `permissions` | 声明所需权限，插件详情展示中文说明，未知权限会拒绝安装 |

目录解析会跳过不兼容的插件，保留其他有效条目。本地导入也使用同一套清单校验。

## 2. 清单格式

目录的外层为 `{"formatVersion":1,"plugins":[...]}`。以下是一个目录条目示例，`path` 和 `sha256` 由目录提供，用来定位并校验安装包。

```jsonc
{
  "formatVersion": 1,             // 插件清单支持 1 或 2
  "id": "nearby-devices",
  "name": "附近设备",
  "author": "yehu-imei",
  "version": "1.0.0",
  "description": "查看附近的蓝牙设备",
  "details": "……",
  "capabilities": ["device.nearby"],
  "path": "packages/nearby-devices-1.0.0.zip",
  "sha256": "…64 hex…",

  // v2 可选字段
  "apiVersion": 2,                 // 默认 1；客户端支持上限 2，超过则跳过
  "minAppVersion": "3.1.2",        // 默认无要求；低于它则跳过该插件
  "permissions": [                // 默认空。目录跳过声明未知权限的条目
    "device.nearby"
  ]
}
```

### 2.1 允许的权限（客户端白名单）

| id | 给用户的说明 |
|---|---|
| `device.nearby` | 读取附近设备 |
| `device.room-filter` | 按寝室筛选设备 |
| `wallet.balance.read` | 读取钱包/一卡通余额 |
| `bill.list.read` | 读取消费账单 |
| `usage.keep-screen-on` | 用水时保持屏幕常亮 |
| `appearance.background` | 修改界面背景 |
| `diagnostics.runtime-log` | 读写运行日志 |
| `action.open-url` | 打开声明过的网页 |
| `action.open-recharge` | 打开官方充值入口 |

白名单由客户端维护。插件只能声明客户端认识的权限，重复的权限项会去重。

### 2.2 `apiVersion` 与 `formatVersion` 的区别

- `formatVersion` 指定清单结构。目录根对象仍为 `1`，目录中的插件条目和包内 `manifest.json` 支持 `1` 和 `2`。
- `apiVersion` 指定最低能力版本，当前客户端支持到 `2`。`minAppVersion` 进一步约束 App 版本。
- 需要让只认识清单格式 1 的早期插件客户端跳过新插件时，将目录条目和包内清单同时设为 `formatVersion: 2`。这些早期客户端不检查 `apiVersion` 和 `minAppVersion`。

## 3. 双源下载

```
主源  https://raw.giteeusercontent.com/yehu-imei/linyu-plugins/raw/main/
备源  https://raw.githubusercontent.com/yehu-imei/linyu-plugins/main/
```

1. 读取目录时先尝试 Gitee。网络错误、HTTP 失败、目录解析或整体验证失败时尝试 GitHub。首份通过校验的目录用于展示。
2. 下载插件时优先尝试提供所选目录的源。网络错误、SHA-256 不一致、安装包解析失败或清单与目录条目不一致时尝试另一源，并使用原目录条目校验。
3. 两处仓库同步同一份 `catalog.json` 和插件 ZIP。SHA-256 用于核对安装包与所选目录一致。下载失败可通过运行日志定位来源。

发布时将版本化 ZIP 与目录一起同步到两个仓库。

```
GitHub 仓库提交 packages/*.zip + catalog.json
        ↓（镜像）
Gitee 仓库同步同一份文件   ← 主源，必须更新
        ↓
客户端校验目录和安装包，必要时尝试另一源
```

## 4. 客户端行为对照

| 场景 | 仅支持清单格式 1 的早期插件客户端 | 当前客户端 |
|---|---|---|
| 遇到 v1 清单 | 正常 | 正常（缺省 `apiVersion=1`、`permissions=[]`） |
| 清单格式 1，`apiVersion: 2` | 按原有字段校验 | 满足其他条件时安装 |
| 清单格式 1，`apiVersion: 3` | 按原有字段校验 | 跳过并记录日志 |
| 清单格式 2，`apiVersion: 2` | 跳过 | 满足其他条件时安装 |
| 遇到未知权限 | 不感知 | **跳过**（fail closed） |
| Gitee 不可用 | 无法加载目录 | 尝试 GitHub |
